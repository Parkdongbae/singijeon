## 2. 저장 방식: 로컬 저장 vs 회원제

| 비교 | 로컬 저장 (`localStorage`) | 회원제(서버 계정) |
|---|---|---|
| 학생 개인정보 | **수집 없음**(이름·이메일 없음) | 이름·이메일·학교 정보 등 수집·보관 필요 |
| 학교 계정 | 필요 없음 | 학교 계정·소셜 로그인 연동, 인증 정책 확인 필요 |
| 오프라인 | **인터넷 없이 동작**(단일 HTML) | 서버 연결 필요, 교실 망 제한에 취약 |
| 개발·운영 | 서버·DB·보안 업무 없음 | 서버 운영, 보안·탈퇴·삭제 요청 처리 필요 |
| 기기 이동 | 다른 기기·브라우저로 기록이 따라가지 않음 | 어디서든 이어서 가능 |
| 교사 확인 | 교사가 한 번에 못 봄(화면 직접 확인) | 학급 현황 집계 가능 |
| 위험 | 브라우저 데이터 삭제·시크릿 모드에서 유실 | 개인정보 유출·법적 책임(아동 개인정보) |

**결정: 로컬 저장.** 이유 ① 학생 개인정보를 받지 않는다 ② 학교 계정 연동·승인 절차가 필요 없다 ③ 오프라인(단일 HTML)에서도 똑같이 동작한다. 단점(기기 간 이동·교사 집계 없음)은 v2 목표(수업 한 차시)에 필요하지 않으므로 감수한다. 키: `singijeon.settings.v1`, `singijeon.progress.v1`(저장 항목은 [04 §4](04_피드백_게이미피케이션_기획서.md)). 「기록 지우기」를 제공한다.

## 3. 그래픽 품질 4단계 (자동 / 낮음 / 보통 / 높음)

화소 비율(`renderer.setPixelRatio`)·그림자 맵 크기(0이면 그림자 끔)·입자 수를 단계별로 정한다. 화소 비율·그림자 값은 PRD §6와 의뢰 기준, **입자 수는 v2 신규 제안**이다.

| 단계 | 화소 비율 | 그림자 | 입자(불꽃+연기) 동시 상한 | 그 밖에 |
|---|---|---|---|---|
| 낮음 | 1 | 0 (끔) | 150 | 안개·톤매핑 유지, 이름표 유지, 연기 입자 절반 크기 |
| 보통 | 1.5 | 2048 | 450 | PCF Soft 그림자 |
| 높음 | 2 | 4096 | 900 | 그림자 소프트 샘플 최대 |
| 자동 | 아래 규칙으로 위 셋 중 하나 | | | 설정에는 「자동」으로 남음 |

공통: 화소 비율은 `min(단계 값, devicePixelRatio)`. 화차 100발은 발마다 입자를 따로 만들지 않고 **전체 입자 상한을 공유**한다(상한을 넘으면 새 입자를 만들지 않음). 품질 변경은 즉시 반영한다(새로 고침 없음).

**자동 선택 규칙 (v2 신규)**:
구현(`src/kit/stage.js`)은 다음과 같다.
1. 시작 단계: CPU 코어 4개 이하이거나 휴대 기기·크롬북이면 `보통`, 그 밖에는 `높음`.
2. 처음 약 4초(240프레임) 동안 느린 프레임(42ms 초과)을 세어, 많으면(70개 초과) 한 단계 내린다. 다시 재어 필요하면 `낮음`까지 내린다. 자동은 올리지는 않는다.
3. 내린 단계는 저장하지 않고(설정은 「자동」 유지) 방문마다 다시 잰다.

성능 기준: 「보통」 내장 그래픽 노트북 30fps 이상, 「낮음」 보급형 태블릿 30fps 이상(PRD §6).

## 5. 브라우저·기기 표

대상: 교실에서 쓰는 환경. 「확인」은 출시 전 검증 대상(아직 실행하지 않음).

| 환경 | 입력 방식 | 확인할 것 | 위험 | 상태 |
|---|---|---|---|---|
| Chrome 데스크톱(Windows·Mac) | 마우스 + 키보드 | 전 기능, 성능 기준 | 낮음 | 확인 예정 |
| Edge 데스크톱 | 마우스 + 키보드 | Chrome과 같은 엔진 — 화면·소리 | 낮음 | 확인 예정 |
| Safari(iPad) | 터치(Pointer Events) | 두 손가락 확대, 사파리 오디오 제한, 주소창 높이 변화(`100vh`) | **중간** — 오디오·뷰포트 | 확인 예정 |
| Android 태블릿(Chrome) | 터치 | 낮은 사양 30fps, 화소 비율 | **중간** — 성능 | 확인 예정 |
| 크롬북(Chrome) | 터치패드 + 터치스크린 | 성능(보급형 CPU), 키보드 | **중간** — 성능 | 확인 예정 |
| 스마트폰(375px) | 터치 | 가로 스크롤 없음, 세로 레이아웃 | 낮음 | 확인 예정 |

- 입력은 **Pointer Events 하나**로 처리한다(마우스·터치·펜). 3D 영역에서 `touch-action: none`(브라우저 확대·스크롤과 충돌 방지), 패널에서는 기본 스크롤.
- 사용 API: WebGL, Web Audio, `localStorage`, `ResizeObserver`, `matchMedia`(색·움직임 설정), 모두 최신 2개 대형 버전에서 지원되는 것만.
- iPad Safari는 주소창이 오르내려 `100vh`가 변하므로 `100dvh`(없으면 `innerHeight` 기반)로 3D 높이를 계산한다.

## 7. localStorage 불가 환경 (시크릿 모드 등)

| 상황 | 증상 | 대응 |
|---|---|---|
| 접근 시 예외(`SecurityError`) | `localStorage` 읽기·쓰기 throw | 모든 접근을 `try/catch`로 감싼다 |
| 시크릿 모드(일부 브라우저) | 쓰기 용량 0 → `QuotaExceededError` | 같은 처리 — 메모리 객체로 대체 |
| 저장소가 비어 있음·값이 망가짐 | `JSON.parse` 실패 | 기본값으로 시작, 망가진 키는 덮어씀 |
| 학교 PC가 종료 때 데이터 삭제 | 다음 수업에 기록 없음 | 정상 동작 — 안내문에 「기록은 이 기기에만 저장돼요」 표기 |
| 버전 불일치 | 옛 `v`값 | `v`가 모르는 값이면 무시하고 새로 시작 |

대응 동작: 저장 불가이면 기록은 이번 방문 동안만 메모리에 두고, **내 기록 창에 한 줄 안내**(「이 브라우저에서는 기록을 저장할 수 없어요. 창을 닫으면 사라져요」)를 보인다. 설정도 같다(바꾸면 그 방문 동안만 적용). 학습 기능은 저장 여부와 무관하게 모두 쓸 수 있다.

## 8. 자동 재생 제한 (소리)

브라우저는 사용자가 조작하기 전의 소리 재생을 막는다.

| 규칙 | 내용 |
|---|---|
| 시작 시점 | 첫 `pointerdown` / `keydown` 뒤에 `AudioContext`를 만들고 `resume()` |
| 그 전 | 소리 없음(첫 방문 도움말의 첫 클릭이 사실상 첫 조작) |
| Safari | `webkit` 접두사 확인, `resume()`이 거절되면 다음 조작에서 다시 시도 |
| 소리 끔 | `AudioContext`를 만들지 않음 |
| 검증 | 페이지 열자마자 소리가 나지 않음, 첫 버튼 누름 때부터 난다, iPad 무음 스위치는 앱이 해결할 수 없음(안내만) |
