# 03. 학습 콘텐츠 스키마

- **목적**: 화면에 나오는 글·수치·퀴즈의 데이터 구조와 쓰는 규칙을 정해, 내용을 고쳐도 코드를 거의 건드리지 않게 한다.
- **이 문서가 답하는 질문**: 각 콘텐츠 필드는 무엇이고 어떤 타입인가? 「쉬운 설명」과 「자세히」는 어떻게 다른가? 새 단계·문항은 어떻게 추가하나?
- **관련 문서**: [PRD](00_PRD.md) §4·5 · [01 계산 규칙](01_핵심로직_계산규칙_명세서.md) · [02 화면](02_화면흐름도_와이어프레임.md) · [04 피드백](04_피드백_게이미피케이션_기획서.md) · [05 MVP](05_MVP범위_기술검증.md) · 코드 [`src/sim.js`](../src/sim.js), [`src/app.js`](../src/app.js)

표기: v1 코드에 있는 필드는 그대로 두고, 새로 더하는 필드·데이터는 **v2 신규**로 표시한다. v1의 필드 이름·값은 바꾸지 않는다.

---

## 1. BUILD — 만들기 10단계

위치: `sim.js`의 `BUILD` (객체 배열). 단계 순서 = 배열 순서.

| 필드 | 타입 | 뜻 | 예시 (1단계) |
|---|---|---|---|
| `key` | string | 단계 ID. 3D 부재 묶음 키와 같음 | `'hub'` |
| `t` | string | 단계 제목(번호 포함) | `'1. 바퀴통 깎기'` |
| `easy` | string | **v2 신규** 쉬운 설명(2문장·60자 안팎) | §5 표 |
| `d` | string | 자세한 설명(v1 그대로) | `'굵은 참나무를 깎아…'` |
| `rec` | string | 기록 딱지 내용. 없으면 `''` | `'바퀴 지름 870mm [화차]'` |
| `est` | string | 추정 딱지 내용. 없으면 `''` | `'바퀴통·살·테의 결구'` |
| `joint` | string \| null | `JOINTS`의 키. 없으면 `null` | `'mortise'` |

단계 key 순서: `hub, spoke, rim, axle, frame, deck, box, tubes, mount, load`.

## 2. JOINTS — 결구 설명

`JOINTS[key] = { nm, d }`. `nm` = 이름(string), `d` = 설명(string). 확대 3D 이름 옆에 「(추정)」을 붙여 보인다.

| key | nm | 쓰이는 곳 |
|---|---|---|
| `mortise` | 장부맞춤 | 바퀴살–바퀴통, 살–테 (1·2단계) |
| `butterfly` | 나비장이음 | 바퀴테 조각 (3) |
| `pin` | 비녀장 | 굴대 끝 (4) |
| `wedge` | 관통장부 + 쐐기 | 수레채–가로대 (5) |
| `tongue` | 제혀쪽매 | 바닥판 (6) |
| `dovetail` | 사개맞춤(주먹장) | 상자 모서리 (7) |
| `halflap` | 반턱맞춤 | 각도 받침–가로대 (현재 BUILD에서 쓰이지 않음) |

**v2 신규** 필드(제안): `easy` — 한 문장 쉬운 풀이(예: `mortise.easy`: 「튀어나온 촉을 구멍에 끼워 맞추는 방법이에요.」). 한자어는 괄호로 풀이.

## 3. ARROWS — 신기전 4종

`ARROWS[key]` (`dae`, `sanhwa`, `jung`, `so`). 단위 mm. 근거 `[병기]`.

| 필드 | 타입 | 뜻 | 예시 (`jung`) |
|---|---|---|---|
| `nm` | string | 이름 | `'중신기전'` |
| `total` | number | 총길이 | `1455` |
| `stick` | number | 안정막대 길이 | `1406` |
| `tube` | object | `{ L, D, t, d, nozzle }` 약통 길이·겉지름·두께·안지름·분사구멍 | `{ L:200, D:28, t:5.7, d:16.6, nozzle:7.2 }` |
| `bomb` | object \| null | `{ L, D, inner? }` 발화통. 소신기전은 `null`, 산화는 `inner: true` | `{ L:25, D:16.6 }` |
| `year` | number | 연도 | `1448` |

관련 상수: `TUBE_BUILT`(복원 약통 `d, D, t, L, kg, sheets, layers`, 근거 `[약통]`), `GIJEON`(`tube{L,W,hole}`, `rows`, `L`, `H`, `[백과]`), `CART`(`wheelD, bodyL, bodyW, maxAngle`, `[화차]`).

구조 메뉴 설명문(`ADESC`)은 현재 `app.js` 안의 객체(`all, dae, sanhwa, jung, so, tube`). **v2 신규**: 모드마다 `{ easy, d }` 두 칸으로 나누어 `content` 파일로 옮긴다(§6).

## 4. FLY — 비행 값

`FLY[key] = { dry, prop, propMin, propMax, cda, rail, bombKg }` (kg·m 단위, 자세한 값·뜻은 [01 문서 §2.1](01_핵심로직_계산규칙_명세서.md)). 콘텐츠가 아니라 **계산 입력**이므로 쉬운 설명은 두지 않고 화면 문구(「가정」 딱지)만 [01 §6](01_핵심로직_계산규칙_명세서.md) 규칙을 따른다.

함께 쓰는 값: `CORES`(`{280:{I, tb}, 350:{I, tb}}`), `TEST_PROP_KG`, `DAMAGE`, `DAMAGE_MAX`.

## 5. BUILD 10단계 쉬운 설명(easy) 제안 **v2 신규**

기준(§7)에 맞춘 제안 문장. 한자어는 처음 나올 때 풀이를 괄호로 붙인다. 글자 수는 공백 포함 약 60~75자.

| # | key | easy (제안) |
|---|---|---|
| 1 | hub | 바퀴 한가운데 굵은 나무통, 바퀴통(곡)을 깎아요. 둘레에 살을 꽂을 구멍도 뚫어요. |
| 2 | spoke | 바퀴살 끝을 깎아 튀어나온 촉(장부)을 만들어요. 그 촉을 바퀴통 구멍에 끼우는 것이 장부맞춤이에요. |
| 3 | rim | 굽은 나무 6조각을 이어 바퀴테를 만들어요. 나비 모양 나무(나비장)로 이음매가 벌어지지 않게 해요. |
| 4 | axle | 굴대(바퀴 가운데를 꿰는 막대)는 몸체에 붙어 있고 바퀴만 돌아요. 끝의 비녀장(빠짐 막이)이 바퀴를 잡아 줘요. |
| 5 | frame | 긴 수레채 2개에 가로대를 꿰고 쐐기(끼우는 조각)를 박아 단단히 짜요. 몸체는 굴대보다 높이 올려요. |
| 6 | deck | 널빤지 한쪽엔 혀, 한쪽엔 홈을 내어 끼워 맞춰 바닥을 깔아요. 이것이 제혀쪽매예요. |
| 7 | box | 상자 모서리를 손가락처럼 엇갈리게 깎아 맞물려요. 사개맞춤이라 하며 못 없이도 빠지지 않아요. |
| 8 | tubes | 구멍 뚫린 나무통 100개를 일곱 층으로 쌓아요. 맨 아래는 10개, 나머지 여섯 층은 15개씩이에요. |
| 9 | mount | 손잡이를 내리면 수레가 뒤로 기울어 신기전기가 하늘을 봐요. 손잡이를 땅에 대면 가장 높은 약 40°예요. |
| 10 | load | 구멍마다 중신기전을 꽂고 층마다 심지(점화선)를 모아요. 불을 붙이면 위층부터 15발씩 100발이 날아가요. |

검수 메모: 4번의 「바퀴만 돌아요」는 `d`의 차축형(굴대 고정) 설명과 일치. 9번의 「약 40°」는 `CART.maxAngle`과 같음([01 §4](01_핵심로직_계산규칙_명세서.md)). 수치(6조각, 100개, 10·15개)는 `d`와 같은 값을 쓴다.

## 6. 화약 카드 3장 **v2 신규** (v1 `POWDER_HTML`을 3분할)

| 카드 | id | 제목 | 내용(v1 출처) | 쉬운 설명(제안) |
|---|---|---|---|---|
| ① | `materials` | 재료 세 가지 | 흑색화약 75:15:10, 연료(숯·유황)·산화제(염초), 염초가 귀했던 까닭 | 화약은 염초·숯·유황 세 가지를 섞어요. 염초가 산소를 줘서 공기 없이도 타요. |
| ② | `saltpeter` | 염초 만들기(10단계) | 『신전자초방』 10단계 + 과학 설명 | 흙과 재를 물에 우려 졸이면 염초 결정이 나와요. 이것을 여러 번 걸러 깨끗이 해요. |
| ③ | `filling` | 약통에 채우기 | 쇠심·속 빈 쇠막대 다지기, 약선구멍 | 약통에 쇠심을 꽂고 화약을 조금씩 다져요. 쇠심을 빼면 불이 타는 구멍이 생겨요. |

필드(제안): `{ id, title, easy, d, steps?: string[], src: string }`. `steps`는 ②의 10단계 문장. **안전 안내**(`safe`)는 카드와 별개로 **세 카드 모두에 항상 보인다**: 「화약류를 만들거나 다루는 것은 법으로 금지되어 있어요. 역사와 원리를 배우는 내용이에요.」(전체 문구는 v1 그대로 `d`에 둔다.)

## 7. 「쉬운 설명(easy) / 자세히(d)」 2단계 난이도 기준

| 기준 | 쉬운 설명 (`easy`) | 자세히 (`d`) |
|---|---|---|
| 분량 | **2문장 이내, 60자 안팎**(공백 포함 최대 75자) | 제한 없음(v1 문장 그대로) |
| 어휘 | 초5 수준 낱말. **한자어는 처음 쓸 때 괄호로 풀이**(예: 바퀴통(곡), 굴대(바퀴 가운데를 꿰는 막대)) | 전통 용어·치수·전문 용어 사용 |
| 수치 | 꼭 필요한 수 하나(100개, 약 40° 등)만 | 치수·단위·근거 |
| 문장 | 「~해요」체, 한 문장에 한 가지 일 | 「~합니다」체(v1) |
| 근거 딱지 | 붙이지 않음 | 기록 / 추정 딱지 붙임 |
| 표시 위치 | 카드 본문(처음 보이는 글) | 「더 알아보기」 안. 설정 「설명 수준: 자세히」면 처음부터 펼침 |

원칙: `easy`가 틀린 말이 되면 안 된다. 단순화하되 `d`와 모순되지 않는다(검수: `easy`의 모든 수치는 `d` 또는 `rec`에 있음).

## 8. QUIZ — 8문항

v1은 배열 `[질문, 보기[4], 정답 인덱스, 풀이]`. v2는 객체로 바꾼다(필드 **v2 신규**).

| 필드 | 타입 | 뜻 | 예시 (3번) |
|---|---|---|---|
| `id` | string | 문항 ID, 기록 키 | `'q3'` |
| `q` | string | 질문 | `'신기전기 하나에 꽂는 중신기전은 몇 발?'` |
| `opts` | string[4] | 보기 | `['50발','70발','100발','150발']` |
| `ans` | number | 정답 보기 인덱스(0부터) | `2` |
| `ex` | string | 풀이(정오 뒤 바로 표시) | `'아래층 10개 + 위 6층 × 15개 = 100개…'` |
| `menu` | string | 관련 메뉴 키(`build/arrow/powder/launch`) — 오답 시 「공부하러 가기」 링크 | `'build'` |

문항별 관련 메뉴 (제안): q1 신기전 이름 시기 → `arrow` · q2 추력 반작용 → `launch` · q3 100발 → `build`(8단계) · q4 차체 높임 → `build`(5·9단계) · q5 약선구멍 → `arrow`(약통 단면) · q6 텀블링 → `launch`(발화통) · q7 산화제 → `powder`(① 재료) · q8 결구 근거 → `build`.

주의: 현재 정답 인덱스가 8문항 중 6개가 1번(두 번째 보기). v2는 보기 순서를 **보여 줄 때만 섞고**(`ans`는 원본 기준 유지) 정답 위치가 한쪽에 몰리지 않게 한다(**v2 신규**). 채점·별은 [01 §9](01_핵심로직_계산규칙_명세서.md).

## 9. MISSIONS — 과녁 미션 3개

| 필드 | 타입 | 뜻 | ① |
|---|---|---|---|
| `id` | string | 미션 ID(기록 키) | `'m1'` |
| `type` | string | 신기전 종류 | `'jung'` |
| `target` | number | 목표 사거리(m) | `200` |
| `tol` | number | 허용 오차(m) | `15` |
| `title` | string | 이름 | `'중신기전 200m 맞히기'` |

3개: ① `jung` 200±15 · ② `so` 120±10 · ③ `dae` 800±40, `req.bomb = false`. 판정·별은 [01 §8](01_핵심로직_계산규칙_명세서.md).

## 11. 근거 딱지 규칙

[01 §6](01_핵심로직_계산규칙_명세서.md)의 분류를 화면에 이렇게 쓴다.

| 딱지 | 글자 | 색 | 붙는 곳 |
|---|---|---|---|
| 기록 | `기록: …` + 출처 약호 | 파랑 | `rec`, 치수표, 실험값 |
| 추정 | `추정: …` | 주황 | `est`, 결구 확대창 이름 옆 |
| 가정 | `가정` | 회색 | 슬라이더 옆(피해 반경·중·소 화약량), 결과 문구 |

- 색만으로 구분하지 않는다: 딱지에 글자를 항상 넣고, 고대비 테마에서는 테두리 모양도 다르게 한다(실선 / 점선 / 이중선, **v2 신규**).
- 출처 약호: `[병기] [백과] [화차] [실험] [약통]`. 전체 서지는 「근거와 출처」 접기(v1 `srcbox`)에 그대로 둔다.
- 쉬운 설명(`easy`)에는 딱지를 붙이지 않는다. 딱지는 「더 알아보기」에서 확인한다.

## 12. 콘텐츠 추가 방법

| 하고 싶은 일 | 순서 |
|---|---|
| BUILD 단계 추가 | ① `BUILD`에 `{key,t,easy,d,rec,est,joint}` 추가 ② `app.js`의 `groups`(부재 묶음)와 `STEP_VIEW`에 같은 `key` 추가 ③ 새 결구면 `JOINTS`와 `buildJoint`에 추가 ④ `rec`을 쓰면 출처 약호 확인 ⑤ 단계 점·`전체 단계 보기`는 길이에서 자동 |
| 퀴즈 문항 추가 | `QUIZ`에 객체 추가(보기 4개, `ans`, `ex`, `menu`). 별 기준(4·6·8개)은 **문항 수 8에 맞춘 값**이므로 문항 수를 바꾸면 [01 §9](01_핵심로직_계산규칙_명세서.md)의 기준도 같이 고친다 |
| 미션 추가 | `MISSIONS`에 객체 추가. 별 아홉 개 합계 등 배지 조건이 미션 수에 의존하면 [04 §5](04_피드백_게이미피케이션_기획서.md) 수정 |
| 배지 추가 | `BADGES`에 추가하고 `check` 조건을 진행 기록 필드로 계산할 수 있어야 함 |
| 신기전·수치 수정 | `ARROWS` 등은 **기록값**이므로 출처 문헌 확인 후에만 수정하고, `npm test`의 재현 테스트([01 §7](01_핵심로직_계산규칙_명세서.md))를 통과시킨다 |

검수 체크: ① `easy`가 §7 기준을 만족 ② 기록 딱지에 출처가 있음 ③ 쉬운 설명과 자세히가 모순 없음 ④ 새 용어는 한자어 풀이 ⑤ 화약 관련 글에 안전 안내가 함께 보임.
